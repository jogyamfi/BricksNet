# Thrift Generated Types

These types are a **hand-ported, curated subset** of the Databricks `TCLIService`
Thrift IDL — only the structs, enums, and service methods that the BricksNet Thrift
backend actually uses. They are marked `[ExcludeFromCodeCoverage]` and carry an
`// <auto-generated>` header so analyzers and coverage tooling treat them as generated.

## Why hand-ported?

The build environment has no Thrift compiler (`thrift`) or the upstream `.thrift` IDL
available, so the wire types were transcribed by hand from the upstream definitions in
`databricks-sql-nodejs/thrift/TCLIService_types.js` and the Java driver
(`databricks-jdbc/jdbc-core`). Field IDs, enum values, and method names match the
upstream service exactly.

## Regenerating from the real IDL

When the IDL and the Apache Thrift compiler are available, prefer replacing this folder
with generated output:

```sh
thrift --gen netstd:wcf=false \
  -out src/BricksNet/Backends/Thrift/Generated \
  src/BricksNet/Backends/Thrift/idl/TCLIService.thrift
```

The `netstd` target emits `Thrift.Protocol` / `Thrift.Transport` based types compatible
with the `ApacheThrift` runtime package referenced by this project.

## Scope limitations

- Only Arrow inline batches (`arrowBatches`) and CloudFetch links (`resultLinks`) are
  materialised when reading a `TRowSet`. Legacy row/column result sets are detected and
  surfaced as an error (`TRowSet.HasColumnarData`); full columnar support is a Phase 7
  concern.
- Parameter values cover string / numeric / boolean arms only.
