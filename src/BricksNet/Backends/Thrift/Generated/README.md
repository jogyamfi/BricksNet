# TCLIService wire types

This folder holds the Thrift types and client framing the BricksNet Thrift backend uses to talk to
Databricks SQL warehouses and all-purpose clusters over the TCLIService (HiveServer2) protocol.

## Where they come from

The types are a **hand-ported subset** of the TCLIService definitions, not compiler output. They
were transcribed from the Databricks-flavoured definitions shipped with the Databricks SQL drivers
for [Node.js](https://github.com/databricks/databricks-sql-nodejs) (`thrift/TCLIService_types.js`)
and [Java](https://github.com/databricks/databricks-jdbc). Those extend the Apache Hive TCLIService
IDL. All three are licensed under Apache-2.0; see [NOTICE](../../../../../NOTICE). Each file carries
a header saying so.

Only the structs, enums and service methods the backend uses are included. Field IDs, enum values
and method names match the upstream service exactly, because they are what goes on the wire.

## Why not generated code

The Apache Thrift compiler (`thrift --gen netstd`) would produce the full IDL, most of which
BricksNet does not use, and the build would depend on the compiler being installed. The hand-ported
subset runs on the `ApacheThrift` NuGet runtime (`Thrift.Protocol`, `Thrift.Transport`) like
compiler output does. The files still carry an `// <auto-generated>` marker and are excluded from
analyzers (see `.editorconfig` here) and code coverage (`[ExcludeFromCodeCoverage]`).

## Changing them

- To add a field, struct or method, port it from the upstream definitions above. Keep the field ID,
  type and requiredness exactly as upstream, and keep the file header.
- Do not change wire semantics to work around a server behaviour. Handle it in the backend
  (`ThriftSessionBackend`, `ThriftOperationBackend`) instead.
- Cover any new message with a round-trip test using `ThriftBinaryEncoder` in
  `tests/BricksNet.Tests/Backends/Thrift`.

## Scope limitations

- Statements always request Arrow results, so they return Arrow inline batches (`arrowBatches`)
  or CloudFetch links (`resultLinks`). Metadata calls (`GetSchemas`, `GetTables`, …) ignore that
  request and return column-based sets (`columns`), which are read too.
- Row-based result sets (`rows`) are not read. If a server returns one, fetching fails with a
  clear error.
- Statement parameter values cover the string, numeric and boolean arms only.
