# BricksNet.EntityFrameworkCore

An Entity Framework Core 10 provider for Databricks SQL, built on the BricksNet ADO.NET driver. It
supports LINQ queries, raw SQL, `SaveChanges`, `ExecuteUpdate`/`ExecuteDelete`, and
`EnsureCreated`/`EnsureDeleted` for development.

> **Status: preview.** The provider is covered by unit and SQL-baseline tests in CI, and by a live
> functional suite that passes against a Databricks workspace (see
> [Testing against a workspace](#testing-against-a-workspace)).

## Getting started

```shell
dotnet add package BricksNet.EntityFrameworkCore --prerelease
```

```csharp
public class Book
{
    public Guid Id { get; set; }              // generated in .NET (time-ordered UUIDv7)
    public string Title { get; set; } = "";
    public decimal Price { get; set; }
    public long Version { get; set; }         // concurrency token you maintain
}

public class StoreContext(DbContextOptions<StoreContext> options) : DbContext(options)
{
    public DbSet<Book> Books => Set<Book>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.HasDefaultCatalog("main").HasDefaultSchema("store");
        modelBuilder.Entity<Book>().Property(b => b.Version).IsConcurrencyToken();
    }
}

builder.Services.AddDbContext<StoreContext>(options => options.UseBricksNet(
    builder.Configuration.GetConnectionString("Databricks"),
    o => o.EnableRetryOnFailure()));
```

```csharp
var cheap = await db.Books.Where(b => b.Price < 10).OrderBy(b => b.Title).ToListAsync();

db.Books.Add(new Book { Title = "Delta Lake in Practice", Price = 39.99m });
await db.SaveChangesAsync();
```

The `samples/BricksNet.Samples` app has a runnable version: `dotnet run -- EfCore`.

## Configuration

### Connecting

`UseBricksNet` accepts any of:

| Overload | Use when |
|---|---|
| `UseBricksNet(connectionString)` | Settings come from configuration. |
| `UseBricksNet(clientOptions, accessToken)` | You build `BricksNetClientOptions` in code (OAuth, proxies, Thrift, ...). |
| `UseBricksNet(connection, contextOwnsConnection)` | You manage a `BricksNetConnection` yourself. |

A connection string looks like:

```
Host=adb-<workspace-id>.azuredatabricks.net;HttpPath=/sql/1.0/warehouses/<id>;Token=<pat>;Catalog=main;Schema=sales
```

`Catalog` and `Schema` set the session defaults, which unqualified table names resolve against. Use
`UseThrift=true` with an all-purpose cluster's HTTP path.

### Provider options

```csharp
options.UseBricksNet(connectionString, o => o
    .EnableRetryOnFailure(maxRetryCount: 6, maxRetryDelay: TimeSpan.FromSeconds(30))
    .MaxBatchSize(1000)          // rows per multi-row INSERT; 1 disables combining
    .KeepSessionAlive(true)      // default: reuse the Databricks session across EF's open/close
    .CommandTimeout(300));       // seconds; 0 (default) means no client-side timeout
```

**Sessions.** EF opens and closes the connection around every operation. With `KeepSessionAlive`
(the default), the Databricks session stays open until the context is disposed, so queries don't
pay to open a session each time. A session idle for longer than `KeptSessionIdleTimeoutSeconds`
(connection-string keyword, default 900) is replaced on the next use rather than reused after the
server may have expired it. `AddDbContextPool` keeps sessions across pooled requests.

**Transactions.** Databricks has no multi-statement transactions. `BeginTransaction` throws
`NotSupportedException`, and so does running inside a `TransactionScope`, rather than silently
ignoring it.

## Modelling for Databricks

### Keys and generated values

Databricks cannot return values the database generates (there is no `RETURNING` or `OUTPUT`), so
every value must be set in .NET:

- **Integer keys are not auto-generated.** Assign them yourself, or use a value generator
  (`HasValueGenerator<T>()`).
- **`Guid` keys** are generated by EF as time-ordered version 7 UUIDs and stored as `STRING`.
- These are **rejected when the model is built**, with an explanation:
  - `ValueGeneratedOnAdd` without a generator, `HasDefaultValue`, `HasDefaultValueSql` and
    `HasComputedColumnSql`;
  - `IsRowVersion` and sequences;
  - `OwnsMany` collections without a key you can set.
- Primary, foreign and unique keys are an EF concept only: Databricks does not enforce them. A
  unique index logs a warning (`BricksNetEventId.UniqueIndexNotEnforced`).

### Catalogs and schemas

Unity Catalog names have three parts. Set a default catalog for the model, and override it per
entity if needed:

```csharp
modelBuilder.HasDefaultCatalog("main").HasDefaultSchema("sales");
modelBuilder.Entity<ArchivedOrder>().HasCatalog("archive").ToTable("orders");
```

This generates `` `main`.`sales`.`orders` `` in queries and DML. A table in a catalog must also have
a schema. Without a catalog, names resolve against the connection's current catalog.

### Views and keyless types

`HasNoKey().ToView("v_sales")` and `ToSqlQuery(...)` work as usual for read-only data.

## Type mapping

| .NET | Databricks | Notes |
|---|---|---|
| `bool` | `BOOLEAN` | |
| `sbyte` / `short` / `int` / `long` | `TINYINT` / `SMALLINT` / `INT` / `BIGINT` | |
| `byte` / `ushort` / `uint` / `ulong` | `SMALLINT` / `INT` / `BIGINT` / `DECIMAL(20,0)` | Databricks has no unsigned types. |
| `float` / `double` | `FLOAT` / `DOUBLE` | |
| `decimal` | `DECIMAL(18,2)` | Use `HasPrecision(p, s)`; at most 38 digits. Query parameters keep their own precision. |
| `string` | `STRING` | `HasMaxLength` does not change the type; use `HasColumnType("VARCHAR(n)")` to enforce a length. |
| `char` | `STRING` | |
| `Guid` | `STRING` | |
| `DateOnly` | `DATE` | |
| `DateTime` | `TIMESTAMP_NTZ` | A wall-clock value; `Kind` is not stored. Microsecond precision. |
| `DateTimeOffset` | `TIMESTAMP` | An instant, read back in UTC; the offset is not stored. Microsecond precision. |
| `TimeOnly` | `STRING` | Stored as `HH:mm:ss[.fffffff]`; sorts correctly. |
| `TimeSpan` | `STRING` | Stored in .NET's `c` format. **Comparisons and ordering are textual and can be wrong** for values with days or negative values. |
| `byte[]` | `BINARY` | |
| enums | underlying integer type | |

Store types are recognised case-insensitively, with aliases (`INTEGER`, `LONG`, `SHORT`, `BYTE`, `REAL`,
`NUMERIC`, `DEC`, `TIMESTAMP_LTZ`) and facets (`DECIMAL(p,s)`, `VARCHAR(n)`, `CHAR(n)`).
`ARRAY`, `MAP`, `STRUCT`, `VARIANT` and `INTERVAL` are not mapped.

## Querying

Standard LINQ works: filtering, ordering, paging (`LIMIT`/`OFFSET`), joins, `Include` (single or
split query), `GroupBy` with aggregates, set operations, `Contains` on lists, and correlated
subqueries. `Take` and `Skip` values are sent as literals, because Databricks requires constant
`LIMIT`/`OFFSET`.

### Translated members and methods

| Area | Translations |
|---|---|
| Strings | `Length`, `ToUpper`, `ToLower`, `Trim()`, `TrimStart()`, `TrimEnd()`, `Trim(char)`, `Substring`, `IndexOf`, `Replace`, `Contains`, `StartsWith`, `EndsWith`, `string.IsNullOrEmpty`, `string.IsNullOrWhiteSpace`, `+`/`string.Concat`, `string.Compare` in comparisons, `Regex.IsMatch` (Java regex syntax), `string.Join`/`string.Concat` over a group |
| Math | `Abs`, `Ceiling`, `Floor`, `Truncate`, `Round` (half-to-even like .NET; `AwayFromZero` supported), `Pow`, `Sqrt`, `Cbrt`, `Exp`, `Log`, `Log10`, `Log2`, `Sign`, trigonometric functions, `Max`, `Min`, and the same on `MathF` |
| Dates | `Year`, `Month`, `Day`, `Hour`, `Minute`, `Second`, `DayOfYear`, `DayOfWeek`, `Date`, `DateTime.Now`/`UtcNow`/`Today`, `DateTimeOffset.UtcNow`, `AddYears`/`AddMonths`/`AddDays`/`AddHours`/`AddMinutes`/`AddSeconds`/`AddMilliseconds`, `DateOnly.FromDateTime` |
| Other | `ToString()` on numbers, `bool`, `char`, `Guid`; `Convert.To*`; `Guid.NewGuid()` (`uuid()`); `byte[].Length` |
| `EF.Functions` | `Like`, `ILike` (case-insensitive), `Greatest`, `Least`, `DateDiffYear`/`Month`/`Day`/`Hour`/`Minute`/`Second` (whole units, `timestampdiff`) |

### Semantics to be aware of

- **String comparison is case-sensitive.** Use `EF.Functions.ILike` or `ToLower()` for
  case-insensitive matching.
- `Trim()` removes spaces only; .NET also removes tabs and line breaks. `IsNullOrWhiteSpace` does
  treat tabs and line breaks as whitespace.
- `Length` counts characters (code points), while .NET counts UTF-16 units, so strings with emoji
  report a shorter length.
- **`DateTimeOffset` parts** (`Year`, `Hour`, ...) are evaluated in the session time zone, which is UTC
  unless you change it.
- `string.Join` over an ordered group (`g.OrderBy(...).Select(...)`) is joined on the client, because
  Databricks does not guarantee `collect_list` order.
- Not translated (EF reports an error): `TrimStart(char)`/`TrimEnd(char)`, `Millisecond`,
  `DateTime.ToString()`, and `Math.Round` with `ToZero`, `ToNegativeInfinity` or `ToPositiveInfinity`.

## Saving data

### SaveChanges

`INSERT`, `UPDATE` and `DELETE` statements are sent one at a time; there is no batching of different
statements.

- **Consecutive inserts into the same table** are combined into one multi-row `INSERT ... VALUES (...), (...)`.
  This is up to `MaxBatchSize` rows (default 1000) and 256 parameters per statement. A combined insert
  is one atomic statement.
- **Optimistic concurrency** uses the affected-row count Databricks reports (`num_affected_rows`).
  An `UPDATE` or `DELETE` that matches no row throws `DbUpdateConcurrencyException`. Mark a property
  you maintain with `IsConcurrencyToken()`:

  ```csharp
  order.Status = "shipped";
  order.Version++;                 // your own token
  await db.SaveChangesAsync();     // UPDATE ... WHERE Id = @id AND Version = @originalVersion
  ```

- **A save that needs several statements is not atomic.** If a later statement fails, earlier ones
  stay committed. The provider marks those entities as saved, so calling `SaveChanges` again does not
  repeat them, and logs `BricksNetEventId.NonAtomicSaveChanges` once per such save. To make a save
  atomic, keep it to one statement (for example, inserts into one table).

### Bulk operations

`ExecuteUpdate` and `ExecuteDelete` run as single statements and return the affected-row count.
Databricks has no `UPDATE ... FROM`, so updates filtered through navigations or `Take` are generated
as `UPDATE ... WHERE EXISTS (...)`. Setting a column from *another* table's values isn't supported.
For that, write a `MERGE INTO` statement and run it with `ExecuteSql`.

## Retries

`EnableRetryOnFailure()` retries:

- throttling and unavailability (HTTP 429/503);
- Delta concurrent-transaction conflicts (`DELTA_CONCURRENT_APPEND`, `DELTA_CONCURRENT_DELETE_READ`,
  ...), which happen when writers touch the same table at the same time.

| Operation | Retried as |
|---|---|
| Queries, `ExecuteUpdate`, `ExecuteDelete` | The whole operation |
| `SaveChanges` | Each failed statement on its own. Statements that already committed are never repeated. |
| `ExecuteSql` | Not retried by EF. Wrap it: `await db.Database.CreateExecutionStrategy().ExecuteAsync(() => db.Database.ExecuteSqlAsync(...))` |

Concurrency conflicts (`DbUpdateConcurrencyException`) are never retried.

## Creating tables for development

`EnsureCreated` creates the model's schemas (`CREATE SCHEMA IF NOT EXISTS`) and tables
(`CREATE TABLE ... USING DELTA`) when none of the model's tables exist yet:

- Columns keep `NOT NULL` and comments (`HasComment`).
- Key constraints and indexes are omitted, because Databricks doesn't enforce them.
- `EnsureDeleted` drops **only the model's tables**, never schemas.
- `GenerateCreateScript()` returns the DDL as a `;`-separated script.
- `CanConnect()` runs `SELECT 1`.

**Migrations are not supported.** `Migrate()` and `dotnet ef migrations` throw. Manage production
schemas with SQL or your usual deployment tooling.

## Differences from SQL Server

| SQL Server provider | BricksNet provider |
|---|---|
| Transactions, `TransactionScope` | Not supported; each statement commits on its own. |
| Identity columns, sequences, defaults | Not supported; set values in .NET. |
| `rowversion` concurrency | Use a property you maintain with `IsConcurrencyToken()`. |
| Case-insensitive collation by default | Case-sensitive comparisons. |
| `Math.Round` | Same result (half-to-even). |
| Batched statements per round trip | One statement per round trip; inserts into one table are combined. |
| Migrations | Not supported; `EnsureCreated` for development. |
| Enforced keys and unique indexes | Not enforced. |
| Latency in milliseconds | Each statement is a network round trip (often 100 ms or more); warehouses may need to start. |

## Performance tips

- Prefer `AsNoTracking()` for read-only queries, and `AsSplitQuery()` for collection `Include`s.
- Insert in bulk through one `SaveChanges` call; inserts into one table become a single statement.
- Use `ExecuteUpdate`/`ExecuteDelete` instead of loading entities to change many rows.
- Keep `KeepSessionAlive` on (the default) and consider `AddDbContextPool` for web apps.
- Aggregate on the server (`GroupBy`, `Sum`, `Count`) rather than materialising rows.

## Diagnostics

| Event | Level | Meaning |
|---|---|---|
| `BricksNetEventId.NonAtomicSaveChanges` | Warning | A `SaveChanges` call is running more than one statement. |
| `BricksNetEventId.UniqueIndexNotEnforced` | Warning | The model has a unique index Databricks will not enforce. |

Both can be changed with `ConfigureWarnings`, for example
`options.ConfigureWarnings(w => w.Ignore(BricksNetEventId.NonAtomicSaveChanges))`.

Databricks errors surface as `BricksNetException`. Its `ErrorClass` holds the Databricks error class
(for example `TABLE_OR_VIEW_NOT_FOUND`), and `IsTransient` tells you whether a retry may succeed.

## Testing against a workspace

`tests/BricksNet.EntityFrameworkCore.FunctionalTests` runs the provider against a real warehouse. It
creates a temporary schema, seeds data, compares results with .NET, and drops the schema afterwards.
It is skipped unless these variables are set:

```powershell
$env:BRICKSNET_EF_HOST     = "adb-<workspace-id>.azuredatabricks.net"
$env:BRICKSNET_EF_HTTPPATH = "/sql/1.0/warehouses/<warehouse-id>"
$env:BRICKSNET_EF_TOKEN    = "<personal access token>"
$env:BRICKSNET_EF_CATALOG  = "<catalog where a temporary schema may be created>"
# Optional: $env:BRICKSNET_EF_USETHRIFT = "true" for an all-purpose cluster
dotnet test tests/BricksNet.EntityFrameworkCore.FunctionalTests --logger "console;verbosity=detailed"
```

The token needs `USE CATALOG` and `CREATE SCHEMA` on the catalog. `--filter Category=Benchmark`
runs only the timing tests.
